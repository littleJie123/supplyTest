# 简介
更改订单物料

# 测试步骤
测试要区分供应商和餐厅端

## 餐厅端

### 新建物料
- 新建物料香蕉（包），修改规格 1包=100g。
- 新建物料苹果（包）
- 新建物料葡萄（包）
- 新建物料番茄（包）
- 配好供应商
### 发送订单并修改
- 发送订单：香蕉2包，苹果3包。状态为 normal，改的是入库草稿。
- 修改：香蕉入库草稿3包（订货数量仍是2包），删除苹果，增加葡萄4包、番茄5包（新增直接写入库数量，订货数量为0）。
- 检查物料3条。订货金额仍是香蕉2包。列表里能看到入库数量。库存不变。

### 入库订单并修改
- 入库。没有另传数量，香蕉用草稿3包，葡萄、番茄用已写入的入库数量。库存为香蕉3包、葡萄4包、番茄5包。
- 调用 UpdateNoteTime，sysAddTime 和 lastUpdateTime 都改成3天前
- 此时状态是 instocked，改的是对账草稿。香蕉对账草稿3包50g，单价改为20元/包，备注「香蕉改入库」。葡萄对账草稿4包。删除番茄，增加苹果对账2包，备注「新增苹果」
- 香蕉入库数量仍是3包。改价后入库金额按3包×20元加葡萄4包×10元。订货金额只含香蕉原来的2包×20元（葡萄是后加的，没有订货数量）。
- 库存流水：香蕉 Instock 数量3、金额60；葡萄数量4、金额40。番茄、苹果没有未删除的入库流水。
- 检查库存：香蕉3包，葡萄4包，苹果、番茄没有库存。
- 检查 listNoteItem 备注，以及 listUpdateHis：香蕉改价、入库数量不变、对账草稿3.5包；葡萄；删除番茄；新增苹果写的是对账数量。

### 结算
- 结算时不另传数量。对账数量用草稿：香蕉3包50g、葡萄4包，苹果用已写入的2包。
- 已对账不能再改。
- 结算金额为香蕉3.5包×20元加葡萄4包×10元加苹果2包×10元。库存仍是结算前的数量。

### 退货并修改
- 从上面的订单退香蕉1包。退货单状态为入库，库存流水类型为 Back。库存香蕉减1包，为2包。
- 退货单已入库，再改数量是对账草稿。把香蕉对账草稿改成2包，单价改为30元/包，并增加苹果对账1包。
- 退货数量仍是1包。退货金额按1包×30元。库存数量不变：香蕉2包，苹果没有库存。
- 香蕉 Back 流水数量为 -1，金额为 0。苹果没有退货流水。

## 供应商端

### 新建物料
- 新建物料白菜（包），修改规格 1包=100g。
- 新建物料萝卜（包）
- 新建物料黄瓜（包）
- 新建物料土豆（包）

### 盘点物料
- 白菜、萝卜、黄瓜、土豆各盘点 100 包。
- 调用修改盘点时间，把盘点日期改成 10 天前。
- 不盘点的话库存是 0，后面发货扣不到库存，看不出变化。盘点在发货时间（3 天前）之前，发货才会扣到这次库存。


### 待接单并修改
- 发送订单：白菜2包，萝卜3包。状态为 normal（待接单），下一列是拣货数量。
- 修改：白菜拣货草稿3包（订货数量仍是2包），删除萝卜，增加黄瓜4包、土豆5包（新增直接写拣货数量）。
- 订货金额仍是白菜2包。库存不变。

### 接单并修改拣货草稿
- 接单，状态为 accept。下一列仍是拣货数量。
- 修改：白菜拣货草稿3包50g。黄瓜的拣货数量已经在明细上，仍显示4包。删除土豆，增加萝卜拣货2包。
- 订货金额不变。库存不变。

### 拣货并修改发货草稿
- 拣货。白菜用草稿3包50g，黄瓜4包，萝卜2包。
- 拣货后改发货草稿：白菜3包50g，黄瓜4包，萝卜1包。拣货数量和拣货金额不变。库存不变。

### 发货并修改
- 发货按发货草稿扣库存。库存应为：白菜 100 包减 3 包 50g，黄瓜 96 包，萝卜 99 包，土豆 100 包。
- 把订单发货时间改成 3 天前。
- 状态已发货，下一列是出库数量。白菜出库草稿2包，单价改为20元/包。黄瓜出库草稿2包。删除萝卜，增加土豆出库2包。
- 发货数量不变：白菜3包50g，黄瓜4包。发货金额为白菜3.5包×20元加黄瓜4包×10元。订货金额为白菜2包×20元。
- 发货流水：白菜数量 -3.5、金额 0；黄瓜数量 -4、金额 0。萝卜、土豆没有未删除的发货流水。
- 删除萝卜后退回其发货库存。库存：白菜 96.5 包，黄瓜 96 包，萝卜 100 包，土豆 100 包。

### 出库并改对账草稿
- 出库按出库草稿：白菜2包，黄瓜2包，土豆2包。库存不变。
- 出库后改白菜对账草稿为4包50g。出库数量不变。

### 结算
- 结算不另传数量。白菜用对账草稿4包50g，黄瓜、土豆用出库数量2包。
- 已对账不能再改。
- 结算金额为白菜4.5包×20元加黄瓜2包×10元加土豆2包×10元。库存仍为发货修改后的数量。

# 注意
未删除的库存流水里，noteItemType + noteItemId + type 不重复。
改价且已入库或已发货时，要同时校验订单金额和 stockRecord。
