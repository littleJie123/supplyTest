# 简介
构造牛肉物料从「仅包」到「1包=100g」后，6/30盘点→手工入库→销售→正常入库→退货→7/31盘点的完整周期数据；**只在期末盘点前校验一次库存**。期末盘点后再用 `/app/note/updatePrice` 改 7/4 入库量价，**改价前后各打一次** `analysyMaterial`。

# 测试步骤
1. **前置**：`PreTest` 仅创建牛肉，初始单位「包」。
2. **6月30日盘点**（改规格前）：牛肉 **0.5包 / 50元**（`cnt=0.5, buyUnitFee=1`）。
3. **设置规格**：`saveBuyUnit` 改为 **1包=100克**（保留「包」为标准单位；按克操作 `buyUnitFee=100`）。
4. **餐品 BOM**：红烧牛肉、水煮牛肉，每份各 **1包**（`buyUnitFee=1`），理论价 100元/包。
5. **7月2日手工入库**：`createHandInstock`，牛肉 **500g / 1000元**（`cnt=500, buyUnitFee=100`，2元/g）。
6. **7月3日销售**：上传 `excel/datas/sales0703.xlsx`（`target=salesRecord`）再 `saveExcel`。红烧牛肉 **2份** + 水煮牛肉 **1份**、营业日期字符串 **2026/07/03** → 消耗 **3包**。
7. **7月4日正常入库**：`createNote` → `sendNote` → `processNote`，牛肉 **2包 / 600元**（`buyUnitFee=1`，300元/包）；再 `updateNoteTime` 到 2026-07-04。
8. **7月5日退货**：从 7/4 订单退 **1包（fee1）**，再 `updateNoteTime` 到 2026-07-05。
9. **期末盘点前校验库存**：牛肉 **3.5包 / 900元**。
10. **7月31日盘点**：牛肉 **1包**（`buyUnitFee=1`）。
11. **改价前物料分析**：`/app/state/analysyMaterial`（begin=2026-07-01，end=2026-07-31），校验牛肉行。
12. **改入库数量和价格**：`listNoteItem` 后调用 `/app/note/updatePrice`，把 7/4 牛肉从 **2包 / 300元** 改为 **3包 / 400元**（`instockCnt=3, price=400, stockBuyUnitFee=1`）。
13. **改价后重算**：`Recal` 后再打 `analysyMaterial`，校验牛肉行，并对比改价前 `theoryCost` 不变、`cost` 变化。

# 注意点
- 6 月没有 31 日，第一次盘点用 **2026-06-30**。必须在改规格之前，此时物料只有「包」。
- `saveBuyUnit` **不改**已有 `unitsId`，标准单位仍是包：按包 `buyUnitFee=1`，按克 `buyUnitFee=100`。
- 7/2 用手工入库（单接口），带 `salesDay=2026-07-02`；7/4 必须走订单入库（`createNote/sendNote/processNote`），不能用盘点或手工入库冒充正常入库。退货只能挂在 7/4 订单上（手工入库不返回可退的 note）。
- 销售走餐品+BOM+excel 上传（`/app/excel/uploadExcel` + `saveExcel`，与 FlowYunxia 销售导入一致）；红烧2份+水煮1份，各 1包/份 = 3包。营业日期写成字符串 `2026/07/03`，不要用 `DateUtil.toExcelDateNum`（UTC 会少一天）。
- 销售 / 正常入库 / 退货 / 改价改量是嵌套 `TestCase`（多接口）；盘点/改规格/手工入库/物料分析各为单个 Action。
- **FIFO**：销售先扣 6/30 盘点批次（0.5包/50元），再扣 7/2 进货（2.5包/500元）。退货再扣 7/2 剩余（1包/200元），与退货单上的 300元/包无关。7/31 盘点 `processSet` 忽略输入成本，从最新批次往旧回填：保留 7/4 批次 1包@300，清掉 7/2 剩余 1.5包 → 1包 / 300元。
- **updatePrice 放在期末盘点之后**：`analysyMaterial` 只统计 `sales` + `inventory`，入库本身不进该接口。只有改完量价后重算期末盘亏，前后两次分析才会不同。接口会从 7/4 起重算后续流水（含 7/5 退货、7/31 盘点）。
- 改价后 FIFO：退货仍扣 7/2 的 1包/200；盘点前库存 4.5包/1500（7/2 剩 1.5包/300 + 7/4 的 3包/1200）；7/31 按最新批次 400元/包回填 → 1包 / 400元，盘亏 3.5包 / 1100元。
- 改订单/退货单时间用 `/app/note/updateNoteTime`，不要用 `/free/update`。
- 只在 7/31 盘点前校验一次库存（Recal + CheckStock + 金额）：退货后 **3.5包 / 900元**。
- `analysyMaterial` 只读 `sales` + `inventory` 的 `costOfChange*-1`（入库/退货不进）。分析区间 begin=7/01、end=7/31，6/30 盘点流水在区间外故无期初盘点，但销售 FIFO 仍扣该批次；7/31 为期末，中间无盘点。
  - 7/3 销售 3包 FIFO：6/30 的 0.5包/50 + 7/2 的 2.5包/500 = **550**
  - 7/2 共 5包/1000：销售扣 2.5包、退货扣 1包（退货不进接口）、盘亏扣剩余 1.5包 → 计入接口的是 4包/800
  - 7/31 盘点：库存 3.5/900→1/300，盘亏 2.5包/600，其中 7/4 批次 1包/300
  - **改价前** allStock=5.5包/1150（期初50 + 7/2的4包800 + 7/4的1包300）。BOM 100元/包：`theoryCost=300`，`costByBomPrice=550`，`diffByCnt=250`，`diffByPrice=600`，`diff=850`。
  - **改价后** 销售仍 550；7/4 改为 3包/1200，盘点前 4.5包/1500，7/31 按 400元/包回填 1包/400，盘亏 3.5包/1100。allStock=6.5包/1650。`theoryCost=300`，`costByBomPrice=650`，`diffByCnt=350`，`diffByPrice=1000`，`diff=1350`。
