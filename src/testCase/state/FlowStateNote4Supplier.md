# 简介
本用例用来测试门店订货数量汇总表

# 测试步骤

## 创建供应商
创建1个供应商账号，创建3个物料。香蕉（1包=1000g）、苹果（1包=10斤）、西瓜（包）,荔枝（斤）

创建3门店账号：门店A、门店B、门店C。 同时在门店新增供应商“测试供应商”。

# 供应商销售情况
同一批数据再调用 `/app/state/stateSales4Supplier`，验证餐厅列表、各餐厅订单和物料。
时间范围与上面三次相同。

- 08-01 供应商接单后拣货，状态为待发货；08-15 已链接后再发单，接单并拣货后也是待发货。
- 门店C的08-01订单再拣货、发货、出库并结算。报表状态为已对账，发货、出库、对账的数量和金额与订货一致。
- 餐厅列表的状态列是该状态下的订单数。
- 还没发货、出库、对账时，对应数量和金额为空。
- 08-15 门店A西瓜按克下单，且克在供应商规格中，销售单位为克、数量 500。
- 门店A香蕉单位瓶不在供应商规格中，销售单位回落到包、数量 5。
- 门店A再退香蕉 1 瓶，供应商退货单时间改为 2026-08-20。供应商退货单状态为已出库（报表里是未对账），数量写在出库数量。数量和订货、出库金额都是负数。
- 门店C再下一张 2026-08-20 的单：荔枝 1 公斤*10 元。供应商接单、拣货、发货后出库，状态为未对账。销售单位为斤、数量 2，发货和出库与订货相同，对账为空。

# 分拣记录汇总
调用 `/app/state/statePicker4Supplier`。分拣人有 3 个：分拣甲、分拣乙写了昵称，分拣丙不写，显示为工蜂加用户 id。创建供应商的用户也不写昵称。
08-01 到 08-15：分拣甲拣门店A两张单（6 次，305 元），分拣乙拣门店B的 08-01（4 次，135 元），分拣丙拣门店B的 08-15（2 次，14 元），创建人拣门店C的 08-01（5 次，150 元）。
08-20 的分拣记录不含门店A退货单，只有门店C的荔枝订货。
